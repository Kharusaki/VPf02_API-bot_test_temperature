# Telegram-бот с контекстом и исследованием temperature / max_tokens

Учебный проект по подключению AI API к Telegram-боту: диалог с памятью, очистка контекста, выбор модели и эксперименты с параметрами генерации через [ProxyAPI](https://proxyapi.ru/docs).

## Возможности

- Telegram-бот на **aiogram 3**.
- Запросы к OpenAI-совместимому API через официальную библиотеку **openai**.
- У каждого пользователя свой контекст диалога в памяти.
- Очистка контекста командой `/reset` или фразой «очистить контекст».
- Выбор модели командой `/model`.
- Настройка `temperature` и лимита токенов прямо в боте.
- После каждого ответа показываются модель, параметры, расход токенов и ориентировочная стоимость в рублях.
- Автоматический fallback на резервную модель при ошибке API.
- Логирование параметров запросов, ответов и ошибок в консоль и `bot.log`.
- Скрипт `experiments.py` для воспроизводимой серии экспериментов и CSV с результатами.

## Стек

- Python 3.10+ (проверено на 3.12.10)
- aiogram 3.x
- openai (официальная библиотека)
- python-dotenv
- aiohttp-socks (для прокси Telegram, опционально)
- ProxyAPI как OpenAI-совместимый провайдер

## Быстрый старт

```powershell
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполните `.env`:

```dotenv
BOT_TOKEN=токен_телеграм_бота
TELEGRAM_PROXY=
OPENAI_API_KEY=ключ_proxyapi
```

`TELEGRAM_PROXY` нужен, если `api.telegram.org` недоступен напрямую (например, используется локальный HTTP/SOCKS5-прокси). Если Telegram открывается без прокси, оставьте переменную пустой. Для работы прокси установлен пакет `aiohttp-socks` (уже в `requirements.txt`).

Запуск:

```powershell
python bot.py
```

Остановка — `Ctrl+C`.

## Как работает контекст

Контекст хранится в оперативной памяти в `ContextManager`:

```python
self._history: dict[int, list[dict[str, str]]] = {}
```

Для каждого пользователя хранится список пар `user` / `assistant`. При запросе собирается:

```text
system prompt + последние HISTORY_LIMIT сообщений + новое сообщение пользователя
```

После успешного ответа пара добавляется в историю. Если история превышает лимит, старые сообщения обрезаются. `/reset` очищает только историю, персональные настройки модели и температуры сохраняются.

Ограничение: контекст не переживает перезапуск бота — это осознанный выбор самого простого варианта по заданию (`dict` в памяти).

## Эксперименты

### Методика

- Промпт: «Придумай короткий слоган для кофейни «Утро» и объясни его в одном предложении.»
- Температуры: `0.0`, `0.7`, `1.3`.
- По 2 прогона на каждую комбинацию.
- `max_tokens = 120` (для `gpt-5-mini` — `max_completion_tokens = 400`, temperature = 1.0).
- Отдельная серия для `max_tokens`: `20`, `60`, `200` на промпте «Придумай 10 коротких слоганов…».
- Стоимость считается по фактическому `usage`: `prompt_tokens` и `completion_tokens` умножаются на цены модели.
- Все 36 запросов выполнены одним скриптом:

```powershell
python experiments.py
```

Результаты сохраняются в `experiment_results.csv` (кодировка UTF-8 с BOM, удобно открывать в Excel). В CSV есть `request_id`, `finish_reason`, расход токенов, стоимость и полный текст ответа.

### Выводы

1. **При `temperature = 0`** ответы `gpt-4.1-mini`, `gpt-4.1-nano` и `gpt-3.5-turbo` полностью повторяются между прогонами. `gpt-4o-mini` сохраняет слоган, но меняет длину объяснения, а `deepseek-chat` даже при t=0 выдаёт разные ответы. Для строгой воспроизводимости лучше выбирать модели OpenAI.
2. **При `temperature = 0.7`** появляется вариативность, но ответы остаются связными. Это рабочее значение по умолчанию.
3. **При `temperature = 1.3`** растёт разнообразие формулировок, но появляются самоповторы названия, грамматические шероховатости и более длинные объяснения. Для креатива это плюс, для продакшена — риск.
4. **Расход токенов зависит в первую очередь от многословности модели, а не от температуры.** Например, `gpt-3.5-turbo` на тот же промпт тратит 146–172 токена, а `gpt-4.1-mini` — 102–115.
5. **`max_tokens` — это потолок, а не цель.** При 20 и 60 токенах ответ обрезается (`finish_reason = length`), при 200 модель заканчивает сама (`stop`). Стоимость при этом определяется фактическими выходными токенами.
6. **`gpt-5-mini` не подходит для эксперимента с температурой:** API принимает только `temperature = 1.0` и требует `max_completion_tokens`. Бот автоматически учитывает это ограничение.
7. **`gpt-4.1-nano` — самый дешёвый**, но при высоких температурах даёт меньше разнообразия и более слабые формулировки. `deepseek-chat` дешёвый и качественный, но возможны задержки и 429.
8. **Итоговая стоимость всех 36 экспериментов — около 0.83 ₽**, поэтому серию можно повторять без заметных затрат.

## Обработка ошибок и логирование

- Ошибки авторизации, таймауты, проблемы соединения, 429 и 400 обрабатываются в `openai_client.py` и превращаются в понятные сообщения пользователю.
- При retryable-ошибке автоматически выполняется запрос к `FALLBACK_MODEL` (по умолчанию `deepseek/deepseek-chat`).
- В ходе экспериментов один запрос к DeepSeek вернул `429 Too Many Requests`; он был повторён, результат добавлен в CSV. Это пример работы обработки ошибок.
- В `bot.log` пишутся модель, temperature, лимит, размер истории, `request_id`, usage, стоимость, время ответа и стек ошибок. Полные тексты сообщений пользователей в лог не пишутся.
- Пользователю после каждого ответа показывается строка с моделью, параметрами, токенами и стоимостью.

## Ограничения

- Контекст хранится в памяти и теряется при перезапуске.
- Нет ограничения частоты запросов на уровне бота.
- История ограничена 20 сообщениями, чтобы не раздувать стоимость запросов.
- Длинные ответы разбиваются на несколько сообщений по 4000 символов.
